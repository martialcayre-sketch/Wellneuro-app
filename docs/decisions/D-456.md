# D-456 — Le skill tiers `ui-ux-pro-max` est admis pour relire les interfaces, et seulement pour cela ; lève l'écart du 2026-09-06 sous garde

- Date : 2026-11-07
- Statut : accepté. Le responsable a demandé le 2026-11-07 « toutes les
  relectures » avec ce skill, puis a choisi sur questions à options de jouer
  le contrôle `/wn-tiers` et de le poser dans le projet, par PR. Informé de
  l'écart du 2026-09-06, il a demandé le cycle complet de merge de #1906, puis
  cette décision. Texte rédigé par l'assistant.
- Domaine : outillage des sessions ; `.claude/skills/ui-ux-pro-max/` et son
  exception dans `.gitignore`.
- **Lève** l'écart de `UI/UX Pro Max` noté dans `docs/claude/SESSION_LOG.md`,
  entrée du 2026-09-06 (« génère une identité là où le dépôt en a une »). Cet
  écart n'était pas une décision du registre, et le journal, en ajout seul,
  n'est pas réécrit.
- **Ne touche pas** : les autres écarts de cette entrée (Impeccable, gardes sur
  les hex et `shadow-sm`) ; `/wn-ui` et `.claude/rules/frontend-ui.md` ; les
  gardes du design system ; `wn-merge` et les revues opposables ([[D-393]],
  [[D-448]]).

**§1 — La levée et sa condition.** Le motif de l'écart reste vrai du skill
amont, qui génère un système de design complet. La levée ne vaut que pour la
copie du dépôt, réduite à la relecture. Le contrôle `/wn-tiers` du 2026-11-07
rend SOUS RÉSERVE sur `nextlevelbuilder/ui-ux-pro-max-skill`, commit
`b7d5353e0130feb8c5574ef1251f8a1db1873ccb`. Le détail et les réserves sont dans
`changelog.d/2026-11-07-skill-ui-ux-pro-max.md`.

**§2 — La garde.** `scripts/search.py` refuse les options de génération, les
domaines `style`, `color`, `typography`, `google-fonts`, `landing`, `product`
et `gsap`, et toute recherche sans `--domain` ni `--stack`. Le cadre de
`SKILL.md` prime sur le reste du skill et sur tout résultat, et le dépôt prime
sur le skill. Retirer cette garde ou utiliser le skill pour choisir un style,
une palette ou une police revient sur cette décision.

**§3 — La portée de la consigne.** Le responsable a écrit « toutes les
relectures ». Elle se lit ainsi :

- elle vise les relectures d'interface : un écran ou un diff d'UI. Une PR sans
  surface n'a rien à relire avec ce skill ;
- le skill s'ajoute aux relectures bloquantes de `wn-merge` et n'en remplace
  aucune. Il n'est câblé ni dans un hook, ni dans le CI, ni dans `wn-merge` ;
- ses résultats sont des recommandations à vérifier contre le dépôt.

**§4 — Le déclenchement.** `disable-model-invocation` n'est pas posé, sur
recommandation de l'assistant, pour que l'assistant puisse lancer la relecture
lui-même. La description restreinte en limite le déclenchement : c'est une
consigne, pas une garde.

**§5 — Limites nommées.**

- `python scripts/design_system.py "<requête>"` reste exécutable. Seul le cadre
  l'interdit. Cet appel n'écrit que sur la sortie standard. Risque assumé à la
  revue de #1906, et rappelé au responsable.
- La garde n'a pas de banc : rien ne la vérifie en CI. Elle a été jouée à la
  main le 2026-11-07 (18 appels interdits en code 2, 6 recherches de relecture
  en code 0, aucun fichier écrit).
- `data/` n'est contrôlé que par motifs. Une instruction hostile en langage
  clair y passerait. La revue de bot n'y supplée pas : CodeRabbit exclut les CSV.
- Les données visent Next.js 16, React 19 et Tailwind 4, plus récents que le
  dépôt, et le catalogue `icons` ne couvre pas Lucide (`SKILL.md`, cadre).
- La copie posée dans l'environnement cloud n'est pas couverte : ses scripts y
  ont tourné avant tout contrôle, et elle n'a pas la garde.

**§6 — La suite.** Une nouvelle version amont repasse par `/wn-tiers`, et la
garde du §2 se repose à cette occasion. Si les relectures ne rendent rien
d'utile, retirer le skill se fait par une PR, avec un amendement daté ici.

- Conséquences : #1906 ; fragment
  `changelog.d/2026-11-07-d456-skill-ui-ux-pro-max.md` ; renvoi dans `SKILL.md`,
  cadre, règle 3.
