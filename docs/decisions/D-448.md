# D-448 — Revue de substitution : la dérogation `wn-reviewer` devient permanente quand aucun bot ne remplit sa condition sur la tête ; GO sur la tête et verdict par constat toujours exigés (amende D-393 §2)

- Date : 2026-11-05
- Statut : accepté — arbitrage du responsable du 2026-11-05, rendu en
  conversation à la session intégrateur (« Je confirme toutes les
  dérogations pour toujours »), puis confirmé à la file B le même jour ;
  forme (décision qui amende [[D-393]] §2) choisie par le responsable sur
  question à options. Texte rédigé par l'assistant.
- Domaine : gouvernance des PR ; `.claude/rules/pr-revue-et-release-db.md`
  §1.6 ; [[D-393]] §2.
- **Amende** [[D-393]] §2, dernière phrase (« Une dérogation du responsable
  reste possible, par PR et jamais reportée, avec `wn-reviewer` en
  remplacement »), par une ligne datée sous ce paragraphe.
- **Ne touche pas** : la revue de CodeRabbit, puis celle de PR-Agent, qui
  restent les deux premières voies ([[D-290]], [[D-393]] §1 et §2) ; les
  quatre conditions de [[D-393]] §2 ; le verdict de chaque remarque (règle
  1.2) ; les étapes 7 bis et 7 ter de `wn-merge` ; les lots gardés par leur
  file — migration, authentification, `.coderabbit.yaml`, `pr_agent.yml`
  ([[D-373]] §3, [[D-393]] §6) ; les retenues de texte posées par une file ;
  l'approbation des release-db ([[D-044]]), qui n'est pas une dérogation de
  revue ; le barème de `docs/claude/POLITIQUE_REVUE.md`.
- Contexte : le dépôt a moins de dix étoiles. CodeRabbit ne revoit plus
  seul et bute souvent sur son quota. PR-Agent n'est pas opposable sur toute
  PR : diff élagué, fichier exclu (constaté sur #1879, où
  `wn-revue-pr-agent.mjs` rendait 1). Chaque fois, la PR attendait une
  confirmation du responsable, PR par PR.

**§1 — La dérogation est permanente.** Si ni CodeRabbit ni PR-Agent ne
remplit sa condition sur la tête ([[D-393]] §2), la revue de l'agent
`wn-reviewer` les remplace sans confirmation du responsable, ni PR par PR,
ni à l'intégrateur. PR-Agent ne compte que si
`node scripts/wn-revue-pr-agent.mjs <N>` rend 0 ; un run vert ne suffit pas.

**§2 — Ce qui reste exigé.** `wn-reviewer` revoit tout le diff, en lecture
seule (`git -C`, `diff`, `show`, jamais de `checkout`), et rend un **GO sur
le sha de tête** ; un commit poussé après ce GO demande une nouvelle revue de
l'écart. Chaque constat reçoit un verdict : corrigé, écarté avec motif ou
routé avec adresse. Les verdicts sont consignés dans un commentaire de la
PR, qui nomme la revue retenue et la raison de l'absence des bots.

**§3 — Hors champ.** Les lots gardés par leur file (migration,
authentification, `.coderabbit.yaml`, `pr_agent.yml`) restent régis par
leurs règles. L'approbation d'une release-db reste un geste du responsable
([[D-044]]).

**Ce qu'elle ne décide pas.** Un passage de `wn-reviewer` en revue par
défaut avant les bots ; un check requis ; la fin de l'essai de [[D-373]].
