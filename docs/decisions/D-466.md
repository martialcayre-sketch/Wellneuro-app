- **Ne touche pas** : CodeRabbit, première revue exigée ([[D-290]],

- Contexte, constaté le 2026-11-09 par l'API GitHub, sur les PR #1780 à
  #1941 :
  - Copilot reçoit une demande de revue à l'ouverture de chaque PR. Elle ne
    vient d'aucune règle du dépôt (aucun ruleset) : c'est le réglage de revue
    automatique du compte du responsable.
  - Du 2026-11-01 au 2026-11-03 (#1795 à #1838), 45 revues réelles,
    40 remarques en ligne, toutes avec un verdict (31 en ligne, 9 dans la
    conversation de la PR).
  - Depuis #1838, chaque revue est un refus : « Copilot was unable to review
    this pull request because the user who requested the review has
    insufficient remaining quota » (103 jusqu'à #1941). Aucune remarque.
  - Aucune API n'expose à une session le quota restant de Copilot : les
    routes de facturation sont hors du périmètre des sessions, seul le refus
    se lit.
  - Copilot ne revoit qu'une fois par demande (règle 1.6, #1159).

**§1 — L'ordre des revues exigées.** Une seule revue de bot est exigée sur
la tête, dans cet ordre :
1. **CodeRabbit**, comme avant.
2. **Copilot**, si CodeRabbit saute la PR (statut `skipping`) ou bute sur
   son quota (« Review rate limited »), **et** si le quota de Copilot est
   présumé disponible (§2). La session le demande alors sur la tête ; il n'est
   jamais demandé avant que CodeRabbit soit dépassé.
3. **PR-Agent**, prouvé selon [[D-393]] §2, si le quota de Copilot est
   présumé épuisé, si Copilot refuse, ou si sa revue n'est pas venue dix
   minutes après la demande. Le délai est une borne de méthode posée par
   l'assistant, non une source : le responsable peut la changer.
4. `wn-reviewer`, si aucun bot ne remplit sa condition ([[D-448]]).

La revue de PR-Agent tourne d'elle-même à chaque push : ses remarques, comme
toutes celles d'un bot, reçoivent leur verdict (règle 1.2), même quand
Copilot est la revue exigée.

**§2 — Le quota présumé.** Le quota de Copilot est présumé disponible tant
qu'aucune revue de Copilot ne dit « insufficient remaining quota » depuis le
1er du mois en cours, en UTC, date de remise à zéro de ses requêtes. Un tel
refus vaut « épuisé » jusqu'au 1er du mois suivant : on passe directement à
PR-Agent, sans redemander Copilot. Le lecteur
`node scripts/wn-revue-copilot.mjs --quota` le dit : `0` seul vaut quota
présumé disponible, `1` épuisé, `2` lecture impossible (jamais lue comme un
`0`).

**§3 — La demande et la preuve sur la tête.** La demande est un geste de la
session : `gh pr edit <N> --add-reviewer @copilot`, une fois par tête. Le
`POST` REST sur `requested_reviewers` ne l'enregistrait pas en 2026-09
(règle 1.6) : la forme `@copilot` de `gh` est à constater au premier usage ;
si elle échoue, la demande passe par l'interface (« Reviewers », Copilot), et
le constat va au journal de la fiche H93. La revue n'est prouvée sur la tête
que par une revue de `copilot-pull-request-reviewer[bot]` dont le
`commit_id` est la tête et dont le corps n'est pas un refus (« Copilot was
unable to review… »). Le lecteur `node scripts/wn-revue-copilot.mjs <N>` le
dit, aux mêmes codes ; le `tete=` de sa ligne `REVUE` est le sha que le
merge vise.

**§4 — Après un push.** Une revue de Copilot ne vaut que sur le sha qu'elle
porte. Un commit poussé après elle appelle une redemande sur la nouvelle
tête, si le quota est encore présumé disponible (§2) ; sinon, ou en cas de
refus, PR-Agent revoit la tête.

**§5 — Les remarques de Copilot.** Elles sont en ligne et dans le corps de
la revue (bloc « Changes recommended » et ses remarques). Chacune reçoit son
verdict (règle 1.2) : en réponse dans le fil, ou dans un commentaire de PR
qui la cite. Clinique, migration et signature de périmètre remontent en
arbitrage (règle 1.8).

**§6 — Pas de revue systématique.** Le responsable coupe la revue
automatique de Copilot dans les réglages de son compte GitHub (geste hors
dépôt, qu'une session ne peut pas faire). Jusqu'à ce geste, la revue faite à
l'ouverture compte si elle porte sur la tête au moment où CodeRabbit est
dépassé ; un refus à l'ouverture vaut constat de quota épuisé (§2).

**Ce qu'elle ne décide pas.** Un check requis pour Copilot ; une demande de
revue de Copilot par l'intégrateur (la file la demande avant de déclarer
« prête ») ; le niveau d'effort de la revue de Copilot ; le forfait Copilot
du responsable.
