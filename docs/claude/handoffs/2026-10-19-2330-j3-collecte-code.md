# Handoff — J3-collecte : le code sous drapeau éteint (D-330 §4)

## Branche et état Git

`lot/j3-collecte-code` (worktree `j3-collecte-code`), partie de `origin/main` c76a4d81. Une PR, sans migration ni `schema.prisma`.

## Objectif

Livrer le code qui consomme les tables de la collecte (H62), sous `WN_PORTAIL_DEPOT_DOCUMENTS` éteint. Le critère de fin du lot est « dépôt prêt, non ouvert » ; l'ouverture viendra avec ACT-4 (H77).

## Décisions prises

- Les prescriptions de D-330 §4 sont tenues :
  - `deposerDocument` prend le dossier `FOR SHARE`, puis le verrou consultatif du trigger (même clé, même ordre) ;
  - les plafonds et le doublon se comptent sous ce verrou, dans une transaction en READ COMMITTED explicite ;
  - les listes passent par des `select` sans `contenu` ;
  - la consultation est un `updateMany` conditionnel qui précède le service du document ;
  - les erreurs ne sont journalisées que par `classeEtCode`.
- L'écran du praticien n'est pas soumis au drapeau. Il ne lit que ce qui a été déposé, pour qu'un drapeau refermé après un premier dépôt ne prive pas le praticien de ses documents. Drapeau fermé et aucun dépôt : l'encart ne s'affiche pas.
- Les bornes d'image du compte rendu sont reprises telles quelles (`preparerImage`). Les imports de `import/depot` passent par l'entrée publiée `biology-library/publie.ts` (D-306 §2), sans dérogation neuve.
- L'encart d'urgence porte la phrase du dépôt validée le 2026-10-14 (D-293 §3). Le texte G-11 est servi tel quel ; un banc le compare au document validé.
- Le lien `?interrupteur=1` ne juge que l'âge, comme « Mes échanges ». Un dossier clos majeur voit donc le lien, et la page lui dit que son suivi est clôturé.
- Limite acceptée : deux corrections simultanées vers la même catégorie écrivent deux lignes identiques ; la catégorie courante reste juste.
